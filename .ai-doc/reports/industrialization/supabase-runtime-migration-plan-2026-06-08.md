# Supabase Runtime Migration Plan - 2026-06-08

## Scope

This plan extends `DEV-IND-007` from shadow migration readiness into the formal runtime migration task `DEV-SUPABASE-DB-001`.

`DEV-IND-007` remains responsible for disposable target safety, migration traceability, and shadow compare evidence. `DEV-SUPABASE-DB-001` is responsible for adding a real Postgres runtime provider and cutting AI_PDM over to Supabase Postgres.

## Current State

- Local runtime data has been reset.
- There are no historical test files to migrate.
- SQLite remains the only current runtime provider.
- Postgres SQL and deny-by-default RLS SQL already exist.
- Local Supabase migration mirror is generated by `npm.cmd run supabase:migrations:sync`.
- Existing Supabase projects `ProJED` and `ProJED_TEST` must not be used.

## Runtime Migration Strategy

1. Create a dedicated `AI_PDM_STAGING` Supabase target after user cost confirmation.
2. Apply committed AI_PDM migrations and RLS plan.
3. Add async DB provider abstraction.
4. Implement Postgres provider and keep SQLite fallback.
5. Migrate repository calls away from SQLite-only APIs.
6. Run staging API/QC/advisor gates.
7. Create and validate `AI_PDM_PROD`.
8. Switch production env to `PDM_DB_PROVIDER=postgres`.
9. Track Supabase Storage as a separate follow-up.

## Gates

- Target guard passes before any migration apply.
- Migration trace hashes match source files.
- RLS is enabled and forced on every public table.
- `anon` and `authenticated` direct table access remains revoked.
- Server-side secrets do not enter frontend bundle.
- Postgres-mode API regression passes.
- Production smoke writes and reads from Supabase Postgres.

## 2026-06-08 Local Evidence

- `supabase:migrations:sync` generated deterministic local migration mirror files.
- `qc:supabase-runtime-migrations` passed 17/17.
- `db:postgres:compare -- --no-write` passed with 64 SQLite tables and 64 Postgres tables.
- `qc:postgres-shadow` passed 21/21.
- `lint` and `build` passed.
- Supabase CLI remains unavailable locally, so formal CLI migration history remains open.
