# 鉦富機械 PDM 使用者管理辦法

文件狀態：試行版
版本日期：2026-08-26
文件負責人：技術主管與系統管理員
適用對象：營銷、研發、採購、生產、品管、主管、系統管理員
適用範圍：新產品開發、重大改良、圖面送審、BOM 管制、技術移轉、設計變更、正式發行與舊版追溯

本文件是給 PDM 使用者看的作業規則。使用者只需要知道：什麼時候要開案、圖號與料號怎麼用、版次怎麼判斷、哪些資料要送審、誰可以核准，以及什麼版本可以拿去生產或對外使用。

管理原則：PDM 不只是存放檔案，而是用來保護圖面、BOM、驗證紀錄、技術移轉與設計變更的共同依據。正式生產、採購、製造交接、安裝、維修與對外分享，都應以 PDM 中標示為「正式發行」的版本為準。

## 1. 先看這張表：我應該做什麼

| 角色 | 主要工作 | 必須注意 |
| --- | --- | --- |
| 營銷／現場人員 | 提供客戶需求、現場限制、使用問題與回饋 | 需求要具體，不能只口頭說明；會影響設計的資訊要留下紀錄 |
| 研發／設計人員 | 建立圖面、BOM、驗證資料與送審資料 | 一般修改沿同一路徑連續進版；只有並行方案才建立研發分支；小版次不得直接作為正式生產依據 |
| 採購 | 依正式發行的 BOM 與規格採購 | 未正式發行或已停用的資料，不得作為正式採購依據 |
| 生產 | 依正式發行的圖面、BOM、作業標準與檢驗表製造 | 小版次不得直接用於正式生產，除非主管核准有條件試用 |
| 品管／檢驗 | 依正式發行的檢驗標準與試車表確認品質 | 檢驗紀錄要能追溯到圖號、料號與版次 |
| 主管／審核者 | 判斷是否核准、退回、技術移轉或設計變更結案 | 核准前要確認需求、風險、驗證與文件已齊備 |
| 系統管理員 | 維護管理辦法、使用權限、資料完整性與異常處理 | 不代替設計審查，只維持系統與管理制度一致 |

## 2. 產品案件先分級

鉦富機械是低量、多客製、重機械設備公司，不應把每張訂單都當成完整新產品開發案。開案前先判斷案件類型，避免流程過重，也避免重大風險沒有驗證。

| 案件類型 | 什麼情況算這一類 | 管理方式 | 常見例子 |
| --- | --- | --- | --- |
| 成熟客製案 | 既有成熟產品，只調整尺寸、材質、配置或安裝條件 | 完成需求確認、設計審查、圖面／BOM、出廠測試與現場驗收即可 | 油水分離槽尺寸調整、攔汙柵材質變更 |
| 重大改良案 | 結構、馬達、刮泥、浮除、控制方式、維修方式或製程方式有重大變更 | 依專案規劃驗證活動，並在 PDM 留存變更風險與驗證證據 | 改馬達規格、改刮除機構、改清理方式 |
| 全新平台案 | 新機型、新平台、新處理原理、新市場或新外銷規格 | 依專案規劃進度，並在 PDM 管制驗證證據與技術移轉 | 新型加壓浮除設備、外銷版標準機 |

若無法判斷案件類型，先由研發、營銷、生產與主管共同確認。分類錯誤會造成兩種風險：把簡單客製案做得太慢，或把重大改良案太快推進生產。

## 3. 先懂基本款：一張圖怎麼連續進版

多數圖面只需要沿同一條路徑往前進版，不需要另外建立研發分支。先記住以下三條基本流程：

- 新產品開發：0.1 → 0.2 → 0.3 → … → 1。
- 正式版 1 發行後第一次設計變更：1 → 1.1 → 1.2 → … → 2。
- 後續設計變更依同樣規則循環：2 → 2.1 → 2.2 → … → 3。

箭頭代表「有新的修改、補正或驗證結果，才建立下一個版次」。如果只是同一個設計方案繼續修改，就沿原路徑連續進版，不必另開分支。

### 3.1 一般連續進版怎麼操作

1. 研發人員在目前圖面選擇「進版」。
2. 系統依目前版次提出下一個研發小版次，例如由 1 建議 1.1、由 1.1 建議 1.2。
3. 一般情況直接接受系統建議；只有需要保留特定未使用小版號時，才選擇自訂小版。
4. 在新工作版完成圖檔、BOM、圖面資料、變更說明與驗證資料後送審。
5. 小版次核准後只代表受控的研發里程碑，仍不得作為正式生產、採購或對外依據。
6. 技術移轉或設計變更結案核准後，才建立下一個大版次並正式發行，例如 0.x → 1、1.x → 2。

### 3.2 各狀態代表什麼

| 狀態 | 使用時機 | 版次範例 | 可以拿來正式生產嗎 |
| --- | --- | --- | --- |
| 開發中 | 新產品開發、概念驗證、草案設計 | 0.1 → 0.2 → 0.3 → … → 0.11 | 不可以 |
| 移轉準備 | 必要驗證證據已完成，準備交給生產 | 0.x | 原則上不可以，除非主管核准試用 |
| 正式發行 | 技術移轉完成，可作為正式依據 | 1、2、3 | 可以 |
| 設變中 | 已發行產品正在修改、驗證或補正 | 1.1 → 1.2 → … | 不可以 |
| 研發里程碑 | 小版次已核准，可追溯但未成為量產基準 | 1.x | 不可以 |
| 設變完成 | 設變驗證與審查完成，正式取代前版 | 下一個大版次，例如 2 | 可以 |
| 舊版保留 | 已被新版取代，但仍需查詢歷史 | 舊版 | 不可以 |

使用者只要記住：小版次代表開發中、驗證中或設變中；大版次代表已完成技術移轉或設計變更結案。一般修改先走連續進版，只有同時存在多個研發方案時才使用分支。

## 4. 版次與研發分支怎麼用

### 4.1 基本版次規則

- 版次是圖面上的修訂編號，送審時必須填寫。
- 系統會依目前圖面與編號管理規則提出建議版次，一般連續進版直接採用系統建議即可。
- 版次只使用數字，不加 V、不使用英文字母，也不把圖號格式當成版次。
- 正式發行使用大版次整數，例如 1、2、3。大版次只能在技術移轉或設計變更核准完成後建立，使用者不得手動輸入、跳號或回退。
- 研發與設計變更工作使用小版次，例如 0.1、0.2、1.1、1.2。小版次即使核准，也只能成為研發里程碑，不得直接成為正式發行版本。
- 小版次要按照次數理解；0.11 是第 11 次小版，不是一般小數，也不是 0.1。

### 4.2 自訂研發小版的限制

有進版權限的研發人員可不採用系統建議，改選同一主版次下尚未使用、且繼續向前的小版尾碼。系統會鎖定主版次，使用者只選小版尾碼；例如目前量產版為 1，可選擇未使用的 1.3，但不能改成 2.3。

自訂小版必須同時符合：

- 主版次與目前研發基準相同；0.x 只能留在主版 0，1.x 只能留在主版 1。
- 小版尾碼為正整數，且大於該研發路徑目前的小版尾碼。
- 同一張圖的相同版次尚未被其他工作或分支使用。
- 不得回退、重用舊版、跨主版、手動建立大版次，或讓小版次直接正式發行。

### 4.3 先看全貌：一個量產基準，可以有多個候選方案

同一張圖在同一時間只有一個目前量產基準。研發分支不是另一個量產版本，而是從目前量產基準出發、暫時並行的候選方案。

例如目前量產版是 1，可以同時保留兩條研發路徑：方案 A 從 1.1 往 1.3 前進，方案 B 從 1.2 往 1.4 前進。這兩個方案都仍在主版次 1 之下，尚未成為正式量產版。

| 內容 | 代表什麼 | 不代表什麼 |
| --- | --- | --- |
| 量產版 1 | 生產、採購與對外使用的共同基準 | 不會因為建立研發方案而改變 |
| 方案 A、方案 B | 從量產版 1 出發的兩種研發方向 | 都還不是正式量產版 |
| 1.1、1.2、1.3、1.4 | 各方案的工作版或已核准研發里程碑 | 核准後也不會自動取代量產版 1 |

使用者判斷方式：

- 還是在修改同一個方案：沿原路徑連續進版，不開分支。
- 必須同時保留兩個以上不同方案：從同一量產基準建立不同研發分支。
- 每個分支都留在同一主版次，且同一張圖的版次不得重複。
- 每張圖同時最多 3 個未結束研發分支；超過時應先決定保留、取消或作廢哪個方案。

### 4.4 選定一條路徑，讓它成為下一個量產版

當公司決定採用方案 A 時，量產版 1 仍維持有效；方案 A 完成設計變更審查並獲准後，才成為量產版 2 的來源。方案 B 保留歷史，但不會自動進入量產版 2。

這個動作是「選定一個方案成為下一個量產版」，不是把方案 A 與方案 B 自動拼在一起。如果量產版需要方案 B 的部分成果，工程師必須先把需要的內容整理進被選定的方案，重新確認並送審後，才能提出採用申請。

畫面、通知與紀錄一律使用「採用為量產版」這個名稱，不使用「合併」來描述這項工作。

### 4.5 量產基準切換後，舊基準的其他路徑停止前進

量產版 2 正式發行後，所有仍從量產版 1 出發的未結束分支，都會成為舊基準方案並停止修改，避免繼續在過期基準上工作。

凍結代表「停止修改但保留紀錄」，不是刪除資料：

| 舊方案目前情況 | 還可以做什麼 | 不可以再做什麼 | 如果仍要繼續方案 |
| --- | --- | --- | --- |
| 工作尚未送審或核准 | 查看內容；負責人取消本次工作 | 編輯、上傳或刪除檔案、執行辨識決策、送審 | 從量產版 2 重新建立研發工作 |
| 已在審核中 | 審核者退回；負責人查看並取消 | 核准、繼續修改或再次送審 | 先收斂舊工作，再從量產版 2 重新建立 |
| 已有核准研發里程碑但未被採用 | 查看歷史；依權限申請作廢 | 沿用舊主版 1 繼續進版 | 從量產版 2 重新建立，並重新確認要帶入的內容 |

重新建立不是單純改版號，而是要求工程師先以最新量產版為基準，重新確認舊方案是否仍適用。

使用者常見判斷：

| 情境 | 正確做法 |
| --- | --- |
| 新產品第一次畫圖 | 建立 0.1 |
| 同一方案開發中修改第二次 | 連續進版為 0.2，不另開分支 |
| 開發中修改第十一版 | 使用 0.11 |
| 技術移轉完成 | 經核准後建立 1 |
| 正式版 1 發行後要設計變更 | 建立 1.1 |
| 同時試作兩個不同方案 | 在同一主版 1 下建立不同研發分支與不重複小版 |
| 分支成果決定量產 | 提出「採用為量產版」，核准後建立 2 |
| 量產版已到 2，還想延續舊 1.x 方案 | 舊方案維持只能查看，從 2 重新建立研發工作 |

## 5. 圖料根號、料號、圖號規則怎麼用

圖料根號、料號與圖號不是同一件事。使用者查資料時可以從任一號碼進入，但判斷責任要分清楚：圖料根號把同一設計主題的圖與料聚合起來，料號代表 BOM 與用料身分，圖號代表圖面與圖檔身分。

### 5.1 編碼原則

新建立的 PDM 資料使用目前的編碼規則；歷史資料仍可查詢與追溯，新資料不得任意沿用歷史格式。

| 號碼類型 | 編號寫法 | 例子 | 使用者要知道的意思 |
| --- | --- | --- | --- |
| 圖料根號 | 一個英文字母加四位數字 | A0001 | 同一設計主題或設計家族的共同入口 |
| 料號 | 圖料根號加上 P 與兩位數字 | A0001-P01 | 可用於 BOM、採購、成本、庫存與製造的零件身分 |
| 製造圖號 | 圖料根號加上 M 與兩位數字 | A0001-M01 | 製造圖的圖面身分 |
| 參考圖號 | 圖料根號加上 R 與兩位數字 | A0001-R01 | 參考圖的圖面身分，不可作為製造依據 |

編碼限制：

- 開頭英文字母只是編號區段，不代表客戶、產品線、專案、部門、生命週期、圖面類型或其他商業分類。
- P 代表料號，M 代表製造圖，R 代表參考圖。
- 參考圖任何狀態下都不得作為製造依據。
- 0000 與 00 為保留號碼，不得使用。
- 圖料根號、料號與圖號都必須以完整文字保留；試算表、匯入、匯出與報表不得把前面的英文字母或數字零去掉。

### 5.2 三個號碼各自代表什麼

| 號碼 | 管理用途 | 不可混用的地方 |
| --- | --- | --- |
| 圖料根號 | 連結核心品名、設計主題、設計家族與圖料關係 | 不代表專案號、訂單號、客戶號或設備序號，也不取代圖號與料號 |
| 料號 | 代表零件、品名、料件類型，以及 BOM、採購、成本、庫存與製造用料身分 | 不代表圖面是否可以製造，也不取代圖號與版次 |
| 圖號 | 代表圖號、圖面用途、製造圖或參考圖分類、圖面版次與圖檔 | 不代表料件是否可以採購，也不代表同一圖料根號下的所有料號都可以使用 |

管理原則：

- 圖料根號是查找與關聯入口，不取代圖號與料號的用途。
- 圖料關係依資料中的關聯維護，不能只靠號碼文字猜測。
- 送審後的審核內容以送審當時的資料為準，不會因後續主資料變更而自動改寫。
- 若圖料根號、料號、圖號或送審資料互相不一致，應回到各自的資料確認，不得用人工記憶或檔名猜測。

### 5.3 圖號與料號使用規則

- 圖號為必填資料。
- 同一圖號與版次不得重複送審。
- 圖號主體不因版次改變；改版時改版次，不改圖號主體。
- 料號為必填資料。
- 同一料號只能指向同一個實體零件，不同零件不得共用料號。
- 同一零件改版時應沿用料號並建立新版次。
- 正式發行的歷史紀錄必須保留，不可因建立新版而被覆蓋或刪除。
- 新版成功正式發行後，舊版轉為歷史版本；可查詢，但不得作為正式製造、採購或對外分享依據。

實務判斷：

| 問題 | 原則 |
| --- | --- |
| 同一設計主題下新增第二個零件 | 沿用圖料根號，新增下一個料號，例如 A0001-P02 |
| 同一設計主題下新增第二張製造圖 | 沿用圖料根號，新增下一個製造圖號，例如 A0001-M02 |
| 只是同一張圖修改尺寸 | 沿用圖號，增加版次 |
| 是不同設計主題、主要功能或製造基準不同 | 建立新圖料根號 |
| 是不同零件或用途不同 | 建立新料號 |
| 只是參考資料或安裝參考 | 使用參考圖號，例如 A0001-R01，不得當製造依據 |
| 舊版已經被新版取代 | 查得到，但不得作為正式製造、採購或對外分享依據 |

## 6. 研發驗證證據怎麼管理

專案進度與里程碑在專案管理工具維護；PDM 保存「設計可行、現場可用、公司做得出來」所需的驗證證據，以及這些證據是否足以進入技術移轉。

| 驗證主題 | 使用者要回答的問題 | 主要參與角色 | 需要留下的紀錄 | 完成後要看到的結果 |
| --- | --- | --- | --- | --- |
| 工程可行性 | 核心機構、材料、零組件與控制概念可不可行 | 研發、生產，必要時採購 | 測試照片、試驗結果、問題清單、初步風險 | 證據完整且日後查得到 |
| 設計符合性 | 完整設備是否符合客戶需求與現場條件 | 研發、營銷、現場、生產、品管 | 需求確認、處理量、安全性、維修性、圖面與 BOM 檢查 | 審核結果與補件狀態清楚 |
| 製程可行性 | 公司能不能穩定做出、裝好、交付與維修 | 生產、研發、品管、採購 | 焊接、組裝、治具、試車、檢驗點、供應商與工時紀錄 | 技術移轉前必要證據齊備 |
| 技術移轉 | 生產是否能依文件正式製造 | 主管、研發、生產、品管、營銷或現場 | 技術移轉檢核表、正式圖面、BOM、作業標準、檢驗表 | 0.x 完成核准後轉為 1 |

成熟客製案仍要有需求確認、圖面／BOM、製造與檢驗依據。重大改良案與全新平台案不得只靠經驗口頭放行。專案管理工具中的階段變更，不會自動取代 PDM 的審核與發行程序。

## 7. 技術移轉何時可以做

技術移轉不是「檔案上傳完成」，而是公司確認這個產品或重大改良已經可以交給生產穩定執行。

技術移轉前至少確認：

1. 待移轉的圖面與 BOM 已審查，並明確選定同一套移轉基準；如曾建立研發分支，已指定採用方案，未採用方案的內容不得混入移轉成果。
2. BOM 已確認，料號、材質、規格與供應商來源清楚。
3. 專案所要求的必要驗證紀錄已完成，重大風險已有處置。
4. 試車、檢驗、安裝與保養重點已寫成文件。
5. 生產部確認可以製造。
6. 營銷或現場人員確認符合客戶使用情境。
7. 總經理或授權主管核准技術移轉。

技術移轉完成後，圖面、BOM、作業標準與檢驗表由 0.x 轉為大版次 1，並進入正式可生產狀態。

## 8. 什麼時候要提出設計變更申請

正式發行後，只要變更會影響製造、採購、安裝、維修、品質、安全、成本或客戶承諾，就要提出設計變更申請。

| 影響項目 | 是否需要設計變更申請 |
| --- | --- |
| 尺寸、材質、結構、焊接方式 | 需要 |
| 馬達、泵浦、電控、感測器規格 | 需要 |
| 處理量、效率、安全性、維修方式 | 需要 |
| BOM、供應商替代、成本結構 | 需要 |
| 檢驗標準、試車方法、安裝方式 | 需要 |
| 純錯字、格式、註解，且不影響製造與檢驗 | 可走文件修正，不升大版次 |

一般設計變更先走連續進版：提出申請 → 1.1 → 驗證 → 1.2 → 補正 → 1.x → 設計變更審查 → 2 正式發行。

只有需要同時保留多個方案時，才建立同主版次研發分支。公司選定其中一個方案後，提出「採用為量產版」；不會自動把其他方案拼入正式成果。大版次 2 正式發行後，其餘仍以主版 1 為基準的分支依第 4.5 節停止修改。

未完成設計變更的小版次不得直接流入正式生產。若因急案必須使用，需由總經理或授權主管核准有條件放行，並記錄風險、使用專案、補救措施與追蹤期限。

## 9. 送審、審核與發布怎麼走

| 步驟 | 使用者動作 | 看到的狀態 | 重點 |
| --- | --- | --- | --- |
| 建立送審 | 研發或負責人上傳圖面、BOM 或相關文件 | 待審核 | 資料不完整不要送審 |
| 審核 | 有權限主管核准或退回 | 已核准／已退回 | 退回後需補正再送 |
| 發布 | 審核通過後發布正式版本 | 正式發行 | 正式發行才可以作為正式依據 |
| 發布未完成 | 發布過程發生錯誤 | 發行異常 | 由系統管理員或負責人排除問題 |
| 舊版保留 | 新版正式發行後舊版轉為歷史版本 | 歷史版本 | 可查詢，不可當正式依據 |

審核規則：

- 研發或設計人員可建立送審，但不可自行核准或退回。
- 研發主管或系統管理員可依角色權限核准或退回。
- 一般案件由一位有權限的審核者核准後即可發布。
- 公司指定需要雙重審核的案件，必須由兩位不同審核者核准；同一人不得重複核准。
- 若任一審核者退回，該筆送審轉為已退回，不再進入發布流程。

## 10. 檔案與表單怎麼準備

每筆送審至少需包含一個檔案。使用者上傳檔案前，應確認檔名、圖號、料號、版次與內容一致。

### 10.1 電子檔檔名管理

- 3D 設計檔以圖料根號作為檔名，並保留原本的副檔名。例如圖料根號為 A0001，零件檔命名為 A0001.SLDPRT，組合件檔命名為 A0001.SLDASM。
- 2D 工程圖與發行用圖檔以完整圖號作為檔名，並保留原本的副檔名。例如圖號為 A0001-M01，工程圖命名為 A0001-M01.SLDDRW，預覽圖命名為 A0001-M01.PDF，加工交換圖命名為 A0001-M01.DWG。
- 同一圖面進版時沿用相同檔名；版次由 PDM 的版次資料管理，不加在檔名中。
- 上傳前應確認 3D 檔所用的圖料根號與 2D 檔所用圖號的圖料根號一致，避免圖檔彼此對錯。

### 10.2 支援檔案類型

| 類型 | 用途 |
| --- | --- |
| PDF | 主要預覽與審核格式 |
| DWG | CAD 圖面交換或加工參考 |
| SolidWorks 零件檔 | 零件設計資料 |
| SolidWorks 組合件檔 | 組合件設計資料 |
| SolidWorks 工程圖檔 | 工程圖設計資料 |
| 其他附件 | 其他必要的補充資料 |

### 10.3 使用表單

新產品開發與設計變更先控制在 7 張表單以內：

| 表單名稱 | 使用時機 |
| --- | --- |
| 新產品開發立案表 | 判斷案件類型與開案 |
| 設計輸入與需求確認表 | 確認客戶需求、現場條件與限制條件 |
| 研發驗證紀錄表 | 留存工程、設計與製程驗證證據 |
| 技術移轉檢核表 | 正式移轉前確認條件 |
| 圖面／BOM 版次管制表 | 確認圖面、料號與 BOM 版次同步 |
| 設計變更申請表 | 正式發行後提出設計變更 |
| 產品正式發行核准表 | 核准大版次正式發行 |

## 11. 發布與同名檔案規則

- 待審核的送審資料可以核准並進入發布流程。
- 已正式發行、已退回或已成為歷史版本的送審資料，不可再次核准。
- 發布未完成時，必須保留問題說明與處理紀錄，供後續追查。
- 新版正式發行成功後，同一零件的舊正式版本會自動轉為歷史版本。
- 不同零件若在正式發行區使用相同檔名，禁止發布，以避免誤用或覆蓋。
- 同一零件進版時可以沿用相同檔名；新版正式發行成功後，舊版成為歷史版本，不視為不同零件的同名衝突。

使用者的實務做法：如果檔名相同但其實是不同零件或不同設備，先改正圖號、料號或檔名，不要直接送審。

## 12. 權限與責任

| 權限項目 | 預設規則 |
| --- | --- |
| 閱讀管理辦法 | 所有已登入使用者可閱讀 |
| 編輯管理辦法 | 只開放系統管理員 |
| 建立送審 | 研發、設計人員或授權角色 |
| 建立一般連續進版 | 研發、設計人員或具圖面進版權限的授權角色 |
| 選擇自訂研發小版 | 具圖面進版權限者；只能選同主版、向前且未使用的小版尾碼 |
| 核准／退回 | 研發主管或系統管理員 |
| 採用為量產版 | 依送審核准權限執行，仍須符合技術移轉或設計變更結案門檻 |
| 正式技術移轉 | 總經理或授權主管核准 |
| 有條件試用小版次 | 總經理或授權主管核准並留下紀錄 |

管理辦法修改後，應同步作為研發、品管、審核、PDM 操作與 AI 助手回答的共同依據。若管理辦法與系統實際行為不一致，應視為流程或系統缺陷處理。

## 13. AI 助手使用限制

- AI 助手只能協助查詢與說明，不代替任何人做審核或資料異動。
- AI 可協助查詢管理辦法、待審核案件、統計資料、送審內容、檔案資訊與 PDM 規則。
- AI 不可代替人員核准、退回、刪除、進版、發布或修改任何 PDM 資料。
- AI 回答管理辦法時，應以目前公布的管理辦法與正式發行紀錄為準。
- 若 AI 回答與管理辦法不一致，以管理辦法與 PDM 正式發行紀錄為準。

## 14. 與 ISO 9001 的對應關係

本管理辦法參考 ISO 9001 的文件管制、設計與開發、變更控制、產品放行、識別追溯與知識保存原則。品質主管應在品質標準改版或公司流程重大調整時，檢視本辦法是否需要更新。

| 管理活動 | 對應的品質管理意義 |
| --- | --- |
| 產品案件分級 | 先判斷風險與流程深度，避免過度或不足管理 |
| 設計需求確認 | 確認客戶需求、現場條件、法規與公司能力 |
| 研發驗證證據 | 用證據確認設計可行、可用、可製造 |
| 技術移轉 | 把設計成果正式交給生產、檢驗與交付流程 |
| 圖料根號、圖號、料號與版次 | 控制設計主題、圖料關係、工程資料與有效版本，避免錯版製造 |
| 設計變更 | 控管變更影響、驗證與正式發行 |
| 正式版本與歷史版本 | 明確有效版本與歷史版本，方便追溯 |
| 審核權限 | 避免未授權放行或同一人重複核准 |

## 15. 系統管理與稽核留存規則

本章給系統管理員、主管與稽核人員使用；一般使用者只需依前述章節操作。

- 系統需保存送審、審核、發布、退回、發行異常與歷史版本的紀錄。
- 系統需保存每次進版的前一版次、下一版次、版次選擇方式，以及同一圖號版次不得重複的檢查結果。
- 系統需保存研發分支的共同量產基準、前一個研發里程碑、建立、取消、作廢、凍結與「採用為量產版」紀錄。
- 系統需保存檔案大小、原始檔名、儲存位置與檔案完整性驗證資料，供追溯使用。
- 資料與檔案必須保持一致；缺少檔案、找不到儲存位置或檔案內容異常，都視為品質異常。
- 雲端檔案區的正式發布必須完整成功；若部分搬移失敗，需完成補救或留下可追查紀錄。
- 需要流程管制的研發工作區與設計變更工作區使用小版次；不需要流程管制的工作區可不填圖號與版次，但正式發行時仍需完整圖號與大版次。

## 16. 已確認規則與待管理層確認事項

### 16.1 已確認的版次與分支規則

- 一般圖面先依第 3 章連續進版；研發分支只用於同一主版次下的並行方案。
- 系統提供下一個建議版次；有進版權限者可選擇同主版、向前且未使用的自訂小版尾碼。
- 大版次只能在技術移轉或設計變更結案核准後產生；小版次不得正式發行。
- 每張圖同時最多 3 個未結束研發分支；同一張圖的版次不得重複。
- 量產版前進後，舊主版分支一律停止修改；不得自動換號、複製或接續到新主版。
- 現階段不做真正的分支內容合併；正式用語為「採用為量產版」。

### 16.2 待管理層確認事項

- 是否排除容易混淆的英文字母；目前新建資料採用完整英文字母區段。
- 歷史編碼資料的長期顯示、匯入與查詢相容方式。
- 圖號、料號、圖料根號的手動例外建立權限與審核方式。
- 一般案件是否維持單人審核，哪些案件需要雙人審核。
- 正式發行區的同名檔案長期策略：維持禁止、封存舊檔，或允許受控版本覆蓋。
- 重大改良案與全新平台案的核准主管。
