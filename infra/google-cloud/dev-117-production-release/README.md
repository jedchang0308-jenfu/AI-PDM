# DEV-117 AI-PDM-owned production release infrastructure

This state owns only AI-PDM release tooling. It reads the existing `ai-pdm-prod` Cloud Run service and `aipdm-prod-runtime` service account. It must not own the application service lifecycle, Cloud SQL, DNS, human session Secrets, Platform, OrgMaster, or shared-foundation resources. DEV-122 adds only `aipdm-prod-solidworks-document-manager-key`, the project-defined custom role `aipdmSolidworksDocumentManagerRuntime` (exactly `secretmanager.versions.add` and `secretmanager.versions.access`), and a binding on that Secret to the existing `aipdm-prod-runtime`. DEV-125 replaced the shared workload credential with database-backed Windows device credentials. Its three legacy provider objects remain temporarily represented by `dev125-legacy-retirement.tf` so an ordinary runner image rotation cannot accidentally delete them; the fixed retirement flow first proves the replacement runtime, then revokes access, removes deletion protection and deletes the Secret. No project-level Secret grant is permitted.

`APP_INFRA_A` uses a source-frozen targeted plan containing the exact `stageA` addresses from `config/release/dev117-production-release-infra-plan.json` while `incident_runtime_enabled=false`. After the owner builder publishes an immutable controller digest, `APP_INFRA_B` uses the same state, sets `incident_runtime_enabled=true`, and plans the complete module. The gate requires all A addresses to remain read/no-op and every B-only address to be present exactly once. Secret values and versions must never enter Terraform or its state.

Before the Stage A plan, the provider executor updates only the existing application's `invoker_iam_disabled` service field and proves that revision, template, traffic, ingress, and default-URL settings did not change. This is the Domain Restricted Sharing-compatible front-door baseline; an `allUsers` IAM binding is forbidden.

The normal value of `dev125_legacy_workload_auth_mode` is `RETAIN`. `UNPROTECT` and `ABSENT` are reserved for the DEV-125 exact-target retirement executor after runtime drain and provider inventory proof. They are not ordinary release or operator inputs. The temporary three addresses are removed from this manifest and source only after their provider deletion receipt is complete.

DEV-122's three SolidWorks Document Manager addresses are gated by `incident_runtime_enabled` and appended to `stageBAdditional`; Stage A stays unchanged and must not be rerun. During the bounded DEV-125 retirement window the complete manifest has 45 A addresses and 44 B additions (89 total), including the three exact legacy retirement addresses above. The SolidWorks Secret has automatic replication, deletion protection, and `prevent_destroy`. No Secret version or value resource is included. The runtime writes and reads numeric versions through the existing verified settings lifecycle and Windows service; provider configuration alone does not prove a key or an online service. Native CAD properties require the separate Windows acceptance evidence.

The backend prefix is `dev-117/production-release/default.tfstate`. Its bucket, numeric GitHub IDs, workflow SHA, approved notification destination, and controller digest are S2 controlled inputs. Never commit live values.
